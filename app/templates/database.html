Entity Relationships

Primary-key and foreign-key relationships between hospital entities.

👨‍⚕️ Department → Doctor A department can have multiple doctors. 1 : N
👤 Patient → Appointment A patient can have multiple appointments. 1 : N
⚕ Doctor → Appointment A doctor can manage multiple appointments. 1 : N
🏥 Patient → Admission Patient admission records are linked to patients. 1 : N
  • Department → Doctor — department_id
  • Patient → Appointment — patient_id
  • Doctor → Appointment — doctor_id
  • Patient → Admission — patient_id
  • Room → Admission — room_id
  • Patient → Treatment — patient_id
  • Doctor → Treatment — doctor_id
  • Patient → Billing — patient_id

Database Normalization

The database follows normalization principles to reduce redundancy and maintain data consistency.

1NF Each field contains atomic values and each record is uniquely identifiable.
2NF Non-key attributes depend on the complete primary key.
3NF Non-key attributes depend only on the primary key, reducing unnecessary data duplication.

About the Database

MediCore Hospital Management Database

The system uses a relational MySQL database to manage patients, doctors, appointments, departments, rooms, admissions, treatments, medicines, billing and users. Foreign keys connect related entities and help maintain referential integrity.
